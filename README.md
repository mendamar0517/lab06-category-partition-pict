# Лаборатори №6: Category-Partition ба PICT

**Оюутны нэр:** О.Мэнд-Амар  
**Оюутны код:** B232270001

## A. Category-Partition аргаар тест тохиолдол боловсруулах

### A1. Сонголт ба утгуудын хүснэгт

Банкны шилжүүлгийн `POST /transfer` хүсэлт дараах параметрүүдтэй.

| Ангилал (Category) | Сонголт (Choice) | Төлөөлөх утгууд |
|---|---|---|
| From account | Дансны төлөв | Valid, Frozen, Missing |
| To account | Хүлээн авагчийн төлөв | Valid, Missing, SameAsFrom |
| Amount | Шилжүүлэх дүн | Zero, Normal, OverBalance, OverLimit |
| Currency | Валютын төрөл | Same, Different |
| Daily limit usage | Өдрийн лимитийн төлөв | Available, Exhausted |

### A2. ERROR, SINGLE болон IF/property ангилал

| Ангилал | Сонголт | Тэмдэглэгээ | Үндэслэл |
|---|---|---|---|
| From account | Valid | [SINGLE] | Бусад алдааны нөхцөлгүй үед амжилттай шилжүүлэг хийх үндсэн утга. |
| From account | Frozen | [ERROR] | Хөлдсөн данснаас шилжүүлэг хийхийг хориглоно. |
| From account | Missing | [ERROR] | Илгээгчийн данс байхгүй үед шилжүүлэг хийх боломжгүй. |
| To account | Valid | [SINGLE] | Хүлээн авагчийн данс хүчинтэй байх нь амжилтын үндсэн нөхцөл. |
| To account | Missing | [ERROR] | Хүлээн авагчийн данс байхгүй үед алдаа буцаана. |
| To account | SameAsFrom | [ERROR] | Илгээгч болон хүлээн авагч ижил данс байж болохгүй. |
| Amount | Zero | [ERROR] | Шилжүүлэх дүн тэг бол `ERROR_BAD_AMOUNT` үүснэ. |
| Amount | Normal | [SINGLE] | Эерэг, үлдэгдэл болон лимитэд багтах хэвийн дүн. |
| Amount | OverBalance | [ERROR] | Хөрвүүлсний дараах дүн дансны үлдэгдлээс их байна. |
| Amount | OverLimit | [ERROR] | Хөрвүүлсний дараах дүн өдрийн лимитээс их байна. |
| Currency | Same | [SINGLE] | Хүсэлтийн валют дансны валюттай ижил тул хөрвүүлэлт шаардлагагүй. |
| Currency | Different | [IF/property] | Валют ялгаатай үед хөрвүүлэлт хийж, үлдэгдэл болон лимитийг хөрвүүлсний дараа шалгана. |
| Daily limit usage | Available | [SINGLE] | Шилжүүлэг хийхэд өдрийн лимит хүрэлцэх хэвийн нөхцөл. |
| Daily limit usage | Exhausted | [IF/property] | Өдрийн лимит дууссан бол эерэг дүнтэй шилжүүлэг `ERROR_LIMIT` үүсгэнэ. |

**Хязгаарлалтын үндэслэл**

1. `From = Missing` үед данс байхгүй тул `Frozen` төлөвтэй зэрэг сонгохгүй.
2. `To = Missing` үед хүлээн авагч байхгүй тул `SameAsFrom`-той зэрэг сонгохгүй.
3. `Amount = Zero`, `OverBalance`, `OverLimit` нь тус тусдаа утгын ангилал бөгөөд нэг хүсэлтэд зөвхөн нэг дүнгийн сонголт байна.
4. `Amount = Normal` үед амжилттай шилжүүлэг хийхийн тулд илгээгчийн данс хүчинтэй, хөлдөөгүй, хүлээн авагч хүчинтэй бөгөөд өөр данс байх ёстой.
5. `Currency = Different` үед хөрвүүлэлтийн дараах дүнгээр үлдэгдэл болон өдрийн лимитийг шалгана.
6. `Daily limit usage = Exhausted` нь шилжүүлгийн дүн эерэг бөгөөд бусад урьдчилсан шалгалтыг давсан үед `ERROR_LIMIT` үүсгэнэ.

**Олон алдаа давхацсан үеийн шийдвэрлэх дараалал**

Энэ лабораторийн тестийн oracle-д дараах дарааллыг сонгов: `ERROR_NO_FROM` → `ERROR_FROZEN` → `ERROR_NO_TO` → `ERROR_SAME_ACCOUNT` → `ERROR_BAD_AMOUNT` → `ERROR_INSUFFICIENT` → `ERROR_LIMIT`. Энэ нь лабораторийн тестэд зориулан сонгосон дараалал бөгөөд бодит API-ийн хэрэгжүүлэлтийн баталгаатай дүрэм биш.


### A2.1. Cartesian product ба хязгаарлалтын дараах тооцоо

Үндсэн дөрвөн параметрийн боломжит утгуудын тоо:

\[
N = 3 \times 3 \times 4 \times 2 = 72
\]

Иймээс хязгаарлалт тавихаас өмнө Cartesian product нь **72 хослол** байна.

Хязгаарлалт хэрэглэхдээ:
- `From = Missing` болон `From = Frozen` нь нэг хүсэлтэд зэрэг байх боломжгүй.
- `To = Missing` болон `To = SameAsFrom` нь нэг хүсэлтэд зэрэг байх боломжгүй.
- `Amount` параметр нэг л утга авна.
- Амжилттай шилжүүлэгт `From = Valid`, `To = Valid`, `Amount = Normal` байх шаардлагатай.

Хязгаарлалтын дараах боломжит хослолын тоо **M**-ийг эдгээр дүрмийг яг ямар байдлаар хэрэгжүүлснээс хамааруулан тооцно. PICT-ийн constrained model-оос гарсан мөрийн тоог Cartesian product-ийн M-тэй адилтгахгүй: PICT-ийн мөрүүд нь хослол хамруулах тестийн багц юм.


Хоёр `IF` хязгаарлалтыг бүх Cartesian product-д хэрэглэхэд:

- `From = Missing` үед `Amount` зөвхөн `Normal` байна.
- `To = Missing` үед `Amount` зөвхөн `Normal` байна.
- Хязгаарлалттай нийт зөвшөөрөгдсөн хослолын тоо: **M = 42**.

Иймээс **N → M = 72 → 42**. Нийт 30 хослол хасагдсан. Энд M нь зөвшөөрөгдсөн бүх хослолын тоо; харин PICT-ийн `transfer.txt`-ийн 13 мөр нь pairwise хамралтыг хангах зорилготой сонгосон тестийн багц юм.

### A3. Тестийн спецификаци

Энэ хүснэгтийн oracle-д `ERROR_NO_FROM → ERROR_FROZEN → ERROR_NO_TO → ERROR_SAME_ACCOUNT → ERROR_BAD_AMOUNT → ERROR_INSUFFICIENT → ERROR_LIMIT` гэсэн лабораторийн давуу эрэмбийг ашиглав. Дансны setup нь хүснэгтэд заасан төлөвийг үүсгэхээр бэлтгэгдсэн гэж үзнэ.

| ID | From | To | Amount | Currency | Setup / нөхцөл | Хүлээгдэх үр дүн |
|---|---|---|---|---|---|---|
| A01 | Valid | Valid | Normal | Same | Үлдэгдэл 1000, өдрийн лимит хүрэлцээтэй; дүн 100 | `201 {"result":"OK"}` |
| A02 | Missing | Valid | Normal | Same | Илгээгчийн данс байхгүй | `200 {"result":"ERROR_NO_FROM"}` |
| A03 | Frozen | Valid | Normal | Same | Илгээгчийн данс хөлдсөн | `200 {"result":"ERROR_FROZEN"}` |
| A04 | Valid | Missing | Normal | Same | Хүлээн авагчийн данс байхгүй | `200 {"result":"ERROR_NO_TO"}` |
| A05 | Valid | SameAsFrom | Normal | Same | From ба To ижил данс | `200 {"result":"ERROR_SAME_ACCOUNT"}` |
| A06 | Valid | Valid | Zero | Same | Amount = 0 | `200 {"result":"ERROR_BAD_AMOUNT"}` |
| A07 | Valid | Valid | OverBalance | Same | Үлдэгдэл 50, шилжүүлэх дүн 100 | `200 {"result":"ERROR_INSUFFICIENT"}` |
| A08 | Valid | Valid | OverLimit | Same | Өдрийн лимитийн үлдэгдэл 50, шилжүүлэх дүн 100 | `200 {"result":"ERROR_LIMIT"}` |
| A09 | Valid | Valid | Normal | Different | Хөрвүүлсний дараах дүн үлдэгдэл болон лимитэд багтана | `201 {"result":"OK"}` |
| A10 | Missing | Valid | Zero | Same | Илгээгч байхгүй, мөн Amount = 0 | `200 {"result":"ERROR_NO_FROM"}` |
| A11 | Valid | Valid | Normal | Same | Дансны үлдэгдэл 1000, өдрийн лимитийн үлдэгдэл 50, дүн 100 | `200 {"result":"ERROR_LIMIT"}` |

**Тайлбар:** A10 нь `ERROR_NO_FROM` ба `ERROR_BAD_AMOUNT` давхцсан жишээ бөгөөд сонгосон давуу эрэмбээр `ERROR_NO_FROM`-ийг хүлээнэ. A11 нь өдрийн лимитийн хязгаарыг шалгана. `OverBalance`, `OverLimit` нь тестийн загвар дахь төлөөлөх утга бөгөөд бодит дүн, үлдэгдэл, лимитийн тоон setup-ийг туршилтын орчинд тодорхой тогтооно.


## B. PICT ашиглан pairwise тест үүсгэх

### B1. Browser загвар: 2-way ба 3-way

`browser.model` нь Browser, Cookies, Popups, Addons, Attacks, Forgeries гэсэн зургаан параметртэй.

| Загвар | Команд | Үүссэн тестийн мөр |
|---|---|---:|
| 2-way | `pict browser.model` | 10 |
| 3-way | `pict browser.model /o:3` | 20 |

2-way нь параметрүүдийн бүх боломжит хос утгыг дор хаяж нэг удаа хамруулахыг зорьдог. 3-way нь гурван параметрийн утгын бүх боломжит гурвалуудыг хамруулахыг зорьдог. Зургаан параметрийн бүрэн Cartesian product нь `3 × 3 × 2 × 2 × 2 × 2 = 144` тест болно.

PICT нь greedy аргаар тестийн мөрүүдийг сонгодог тул хамгийн бага боломжит мөрийн тоог заавал олно гэсэн баталгаа байхгүй. Иймээс гаралтын 10 болон 20 мөрийг PICT-ийн бодит үр дүн гэж тайлагнаж, лекцийн гараар байгуулсан тестийн тоотой шууд адилтгахгүй.

### B2. Шилжүүлгийн загваруудын харьцуулалт

| Загвар | Үндсэн зарчим | Үр дүнгийн файл | Тестийн мөр |
|---|---|---|---:|
| `transfer-nc.model` | IF хязгаарлалтгүй | `results/transfer-nc.txt` | 13 |
| `transfer.model` | Хоёр IF хязгаарлалттай | `results/transfer.txt` | 13 |
| `transfer-neg.model` | Алдаатай утгуудыг `~`-ээр тэмдэглэсэн | `results/transfer-neg.txt` | 16 |

`transfer-nc.model` нь олон алдааны нөхцөл нэг мөрөнд давхцах боломжтой. `transfer.model` нь `From = Missing` эсвэл `To = Missing` үед `Amount = Normal` байх хязгаарлалттай. Энэ хоёр загварын мөрийн тоо хоёулаа 13 боловч сонгосон мөрүүд нь ялгаатай.

`transfer-neg.model`-д `~Frozen`, `~Missing`, `~SameAsFrom`, `~Zero`, `~OverBalance`, `~OverLimit` зэрэг negative утгууд орсон. PICT-ийн negative-value дүрэм нь нэг мөрөнд хамгийн ихдээ нэг negative утга байхаар загварчлахад тусалдаг. Гаралтад 16 тестийн мөр үүссэн бөгөөд happy path болон алдааны төлөөлөх утгууд багтсан.


### Category-Partition ба PICT-ийн харьцуулалт

A3 хэсгийн 11 гар аргаар боловсруулсан тест нь бизнес дүрэм, хүлээгдэх үр дүн болон давхар алдааны precedence-ийг тодорхой тайлбарладаг. Харин PICT нь параметрийн утгуудын хослолыг системтэй хамруулахад чиглэсэн тестийн багц үүсгэдэг. Тиймээс эдгээр хоёр аргын тестийн тоог шууд адилтгаж болохгүй: гар аргаар боловсруулсан тестүүд тодорхой шаардлага, oracle-ийг шалгахад, PICT-ийн мөрүүд хослолын хамралтыг нэмэгдүүлэхэд тусална.

Browser загварын PICT 2-way үр дүн 10 мөр бөгөөд лекцийн гараар байгуулсан 9 мөрөөс нэгээр олон байна. Энэ нь PICT заавал хамгийн цөөн мөртэй багц олдог гэсэн үг биш; гаралт нь загвар, хамралтын түвшин болон greedy сонголтоос хамаарна. 3-way үед 20 мөр гарсан нь 2-way-ээс илүү өндөр түвшний хослолын хамралт шаардсантай холбоотой. Browser загварын Cartesian product нь 144 боломжит хослолтой боловч PICT-ийн 10 болон 20 мөр нь бүх хослолыг жагсаасан хэрэг биш.

### B3. PICT гаралтаас сонгосон бодит тест кейсүүд

Дараах гурван тестийн мөрийг `results/transfer-neg.txt` файлаас сонгосон. `Normal` болон `Zero` нь PICT загварын ангилал тул request body-д бодит тоон утга ашиглав. Эдгээр нь бизнес дүрмээр тооцсон хүлээгдэх үр дүн бөгөөд бодит API ажиллуулсан үр дүн биш.

#### TC-P1 — Happy path

**PICT мөр:** `Valid | Valid | Normal | Same`

**Setup:** From данс `1001` хүчинтэй, хөлдөөгүй, үлдэгдэл `1000 MNT`; To данс `2002` хүчинтэй бөгөөд өөр данс; өдрийн лимитийн үлдэгдэл `500 MNT`.

**Request:** `POST /transfer`

| Талбар | Утга |
|---|---|
| `from` | `"1001"` |
| `to` | `"2002"` |
| `amount` | `100` |
| `currency` | `"MNT"` |

**Oracle:** `201 {"result":"OK"}` — дүн эерэг, үлдэгдэл болон өдрийн лимитэд багтсан.

#### TC-P2 — Amount тэг байх алдаа

**PICT мөр:** `Valid | Valid | ~Zero | Same`

**Setup:** From данс `1001` хүчинтэй, хөлдөөгүй, үлдэгдэл `1000 MNT`; To данс `2002` хүчинтэй, өөр данс; өдрийн лимит хүрэлцээтэй.

**Request:** `POST /transfer`

| Талбар | Утга |
|---|---|
| `from` | `"1001"` |
| `to` | `"2002"` |
| `amount` | `0` |
| `currency` | `"MNT"` |

**Oracle:** `200 {"result":"ERROR_BAD_AMOUNT"}` — шилжүүлэх дүн тэг тул зөвшөөрөгдөхгүй.

#### TC-P3 — Хөлдсөн данснаас шилжүүлэх алдаа

**PICT мөр:** `~Frozen | Valid | Normal | Same`

**Setup:** From данс `1001` хөлдсөн, үлдэгдэл `1000 MNT`; To данс `2002` хүчинтэй, өөр данс; өдрийн лимит хүрэлцээтэй.

**Request:** `POST /transfer`

| Талбар | Утга |
|---|---|
| `from` | `"1001"` |
| `to` | `"2002"` |
| `amount` | `100` |
| `currency` | `"MNT"` |

**Oracle:** `200 {"result":"ERROR_FROZEN"}` — илгээгчийн данс хөлдсөн тул шилжүүлгийг хориглоно.


## Дүгнэлт

Энэ лабораторийн ажлаар Category-Partition болон PICT аргыг ашиглан тестийн тохиолдол боловсруулах аргачлалыг судаллаа. Category-Partition аргаар банкны шилжүүлгийн оролтын ангилал, утгууд болон алдааны нөхцөлүүдийг тодорхойлсон. Үндсэн дөрвөн параметрийн Cartesian product нь 72 хослолтой бөгөөд хоёр IF хязгаарлалт хэрэглэсний дараа 42 зөвшөөрөгдсөн хослол үлдсэн. Гар аргаар боловсруулсан спецификацид амжилттай шилжүүлэг, алдааны ангилал бүр болон давхар алдааны жишээг оруулсан. PICT-ээр browser загварын 2-way үед 10, 3-way үед 20 тестийн мөр үүсгэсэн. Шилжүүлгийн хязгаарлалтгүй болон IF хязгаарлалттай загвар тус бүр 13 мөр, negative-value загвар 16 мөр гаргасан. PICT-ийн greedy арга нь параметрийн хослолуудыг хамруулах тестийн багцыг автоматаар сонгодог боловч хамгийн бага боломжит мөрийн тоог заавал баталгаажуулдаггүй. Category-Partition нь алдааны утга, бизнес дүрэм, давуу эрэмбийг хүн өөрөө тодорхойлдог тул хүлээгдэх үр дүнг нарийвчлан тайлбарлахад илүү тохиромжтой. Энэ ажлын хамгийн их анхаарал шаардсан хэсэг нь олон алдаа давхцах үед oracle-ийг тогтоох болон зөвшөөрөгдсөн хослолын тоог PICT-ийн тестийн мөрийн тооноос ялгаж ойлгох байлаа.
